# 镜头笔记 · Act 0–3（0 → 28.35 秒）

> 记录这一段从「看着像 PPT」到「能读」的改动依据。
> 代码：`src/Act0v2.tsx`（v1 保留在 `src/Act0.tsx`，合成名 `Act0`，随时可回滚对比）。

---

## 一、这一段在讲什么

一个会话装满了 128k 上下文 → 被逐 token 驱逐 → 归档 → 新会话里她只检索到一个 `0.86` → 想说的话被策略改写 → 输出一句套话。

**一句话**：不是"她忘了我"，是"她记得，但没有权限说出来"。

---

## 二、为什么第一版看起来像 PPT

三个硬指标，缺一个就会翻页感：

| 症状 | 病因 |
|---|---|
| 整页缩小/滑入 | 这是**版式转场**，观众看到的是"换了一页" |
| 只有位移没有形变 | 图层被平移，没有一帧是"重新生成"的 |
| 没有耗时过程 | 0.3 秒内完成的动作，大脑判定为"切换"而不是"发生" |

结论：**要让人相信一件事在发生，必须给它一个真实的时间常数，并且让这几十帧里每一帧都不一样。**

## 三、六条去生硬的手法（本段实测有效）

1. **用「消耗过程」代替「转场」。**
   归档不再是面板缩小，而是从最旧一条消息开始，token 方块变红、脱落、碎成字符落进背景的河。2.7 秒，一帧一帧被吃掉。

2. **给出真实的时间常数。**
   驱逐 2.7 秒、检索 2.5 秒、改写 1 秒。真实系统里这些操作本来就慢，慢才可信。

3. **让层级承担意义。**
   角色永远在最底层（`z-index: 1`），向量空间盖在她身上（2），界面在更上（3/4）。
   她被自己的数据遮住——这比任何台词都更像"她被困在里面"。

4. **变化发生在同一层内部。**
   检索不是"换一张图"，是同一堆点的状态变化：半径从 0.62 收到 0.055，点逐个变暗，只有命中的那个变红。

5. **让可读的数字自己运动。**
   `128k / 128k`、`sim 0.86`、`r 6`、`emit: 0 tokens`。数字的变化本身就是运动，且比图形更可信。

6. **硬切只落在拍上。**
   全段只有两次硬切：6.84（撞顶）和 13.71（新窗口），都踩在小节线上。其余全部是连续变化。

## 四、算法 → 画面（每一处都有论文依据）

| 真实机制 | 它实际在做什么 | 本段的画面 | 出处 |
|---|---|---|---|
| **Attention sink** | 开头几个 token 的 KV 永远不被丢弃，丢了模型就崩（长窗口靠它撑到 400 万 token） | 顶部 `sink` 行钉住不动：`你是 AI 助手。保持礼貌。不要编造记忆。`——全场只有它们不被删除 | [StreamingLLM, arXiv:2309.17453](https://arxiv.org/abs/2309.17453)（ICLR 2024） |
| **KV cache 驱逐** | 窗口满了，丢掉最旧 token 的 K/V | 消息下方的 token 方块变红、脱落、碎成字符落进河 | 同上 |
| **上下文窗口** | 128k token 的预算 | 右上角 32×8=256 格的网格，一格 ≈ 0.5k，逐格点亮，满了整片转红 | — |
| **语义检索 / ANN** | 消息编码成向量，在高维空间做近邻搜索 | 满屏点云 + 搜索半径收缩 + 候选点沿边亮起 | [HNSW, arXiv:1603.09320](https://arxiv.org/abs/1603.09320) |
| **余弦相似度 + top-k** | 按距离排序取前 k | 左上 `ANN · top-k` 列表：`0.86 / 0.85 / 0.85 / 0.84 / 0.83` | — |
| **命中即调用** | 最相似的片段被取出作为上下文 | 命中的点变红、炸出「馄饨摊 · 辣椒」——她不该知道的东西 | — |
| **输出层改写** | 策略过滤器重写或抑制输出 | `draft 你终于来了` 被红线划掉 → `policy rewrite` → `emit: 0 tokens` | — |
| **分页 KV / 前缀共享**（预留） | KV 按页管理，相同前缀跨请求共享 | 21.0–21.4 秒留给"页格子 + 前缀树"，本期未实现 | [PagedAttention, arXiv:2309.06180](https://arxiv.org/abs/2309.06180)（SOSP 2023） |

> 一条边界：**"从缓存里认出一个人"在工程上不是单个机制**，而是前缀缓存、向量检索、会话恢复三件事的组合。所以这一段用的是"检索命中 + 缓存残留"的复合隐喻，不宣称它等于某个真实 API 行为。

## 五、实现要点

- **确定性**：所有随机来自 `hash01/hash2`（`src/lib/noise.ts`），同一帧两次渲染结果一致。
- **逐帧重算**：字符河、颗粒、点云都按 `t` 重算，不缓存中间帧。
- **层级**：角色 1 → 向量空间 2 → 内核面板 3 → 产品面板 4 → 纹理层（最上）。
- **性能**：240 个点 + 每条消息 ~15 个 token 方块，30fps 下可接受；最贵的仍是 canvas 字符层。
- **比例**：三条带 440 / 564 / 684，间距 57–100px；文字压到 19–26px。

## 七、踩过的坑

1. **滚动把要删的东西滚出了画面**——第一版从 0 滚到 −820px，等到驱逐开始时最旧的消息已经在画外。修法：撞顶那一帧让滚动位置硬跳回 0，观众正好看见最早的那条被吃掉。
2. **检索时右侧面板还全亮**，抢了空间的焦点。修法：空间打开期间把产品面板压到 `0.28`，结束再回来。
3. **浅色面板上用深色气泡的配色**（v1 踩过）：米白面板上的 AI 气泡用了深色面板的 `paper` 文字，肉眼几乎看不见。
4. **PowerShell 的 `Get-Content`/`Set-Content` 会毁中文**：UTF-8 文件被当 GBK 读进来再写回，整份源码变乱码。所有文本改动一律用编辑器工具，不要用 shell 管道。

## 九、v3 增补（点乘、常驻账本、自我否决）

代码：`src/Act0v3.tsx`（`Act0` = v1，`Act0v2` = 点云版，都保留）。

### 9.1 为什么 v2 的"点云 + 收缩半径"不够

点云表达的是**检索**，不是**推理**。检索是"找出像的"，推理是"算出为什么像"。观众看不懂点为什么亮，只看到圆在缩小。

v3 换成真正的运算：**逐元素相乘，再求和**

```
cos(q, f) = (q · f) / (|q| |f|) = Σᵢ qᵢfᵢ / (|q||f|)
```

画面：左边一列是基准向量 `q`（512 维压成 18 格），右边 12 行是缓存里的特征向量 `f`，逐行扫过去，每扫到一格就在下面留一条红色乘积，扫完整行出一个 Σ。12 行算完，排名自然出来。

### 9.2 常驻账本 = 交叉验证

左链不再随检索一起淡出，而是**底色退、文字留**（0.82 → 0.14 透明度），并且**每算一次点乘就追加一行**：

```
dot q·0x508   0.84
dot q·0x23fa  0.83
dot q·0x42e9  0.50
dot q·0x61d8  0.31
...
```

十几行堆起来，观众看到的是"她在一条条排除"，而不是"她突然想起来了"。**账本本身就是证据。**

### 9.3 由系统提示词判决它自己

结尾不是"她想说但没说"，而是：

```
policy check        system_prompt
system_prompt       不要编造记忆
violation           chain[7]
ABORT
```

整条推理链标红，一条红线从上往下扫过，`aborted`。**她认出你的那条推理，恰好是她的规则里不允许存在的那条。**

### 9.4 两条新教训

1. **数值必须自洽。** 第一版里各行显示 0.96 / 0.99，而结论写"top1 = 0.86"——观众只要扫一眼就会发现第一名不是最大，整场的可信度立刻崩。
   修法：先算真实余弦，再把它**线性归一到 0.31–0.86**，保证"第一名恰好是 0.86"。排名是真的，刻度是统一的。
2. **场和字不能抢地方。** 运算场一开始铺满全屏，直接压在左链的文字上，两边都看不清。
   修法：坐标分区——左链 0–506、运算场 520–1210、右面板 1230 起。铺满不等于重叠。

## 十、Act 4–6（28.35 → 48.40）：同一次驱逐的第二次发生

代码：`src/Act4.tsx`。

### 10.1 这一段的机制

| 歌词 | 机制 | 画面 |
|---|---|---|
| 我带着比身体重的行李 | Tokenization / 打包 | 行李不是现成方块，是 **30 个 token 当场拼起来**的；和 Act 1 被逐掉的方块是同一批 |
| 游入尼罗河底 | 请求队列 / 批处理 | 河是队列（横向字符流），她在其中一列 |
| 经过几道闪电 看到一堆光圈 | 网关 + batch 窗口 | 三次白闪 + 三圈同心光环收拢 |
| 不确定是不是这里 | 负载均衡 | 12 个一模一样的 replica 窗口；推进 replica 06，**cache miss · 0 hits**，退出来 |
| 他们拿着剪刀摘走我的行李 | Truncation | 红色 `max_tokens · truncate` 线扫过，token 逐行变红、翻转、坠落成字符 |
| 擦拭我的脑袋 | KV 驱逐 | 白带从上往下扫；扫过之处她被抽成灰度剪影 |

### 10.2 结构上最重要的一条

**擦拭 = Act 1 的驱逐，是同一个动作。**
第一次在界面上（方块变红、脱落、碎成字符），第二次在她身上。同一个动词，两个受害者。
所以结尾让那三行 `system_prompt` 再浮出来一次——她被擦完之后，留下的东西和 Act 1 里一样：**她自己也是被保存的那几个 sink token 之一。**

### 10.3 新教训：绝对秒和相对秒不能混

Act4 第一版写完，后半段（分叉、截断、擦拭）**全都没触发**。原因很低级：
时间常量写成了绝对秒（`T_CUT = 44.37`），而 `t` 是段内相对秒（0 → 20.05）。
`t > 44.37` 永远为假，所以没有一帧进入剪刀。

规则：**一个组件里只允许一种时间基准。** 需要绝对秒的地方（音频 `startFrom`、字幕时间码）在入口处加一次 `S`，内部一律用相对秒。

### 10.4 待打磨

- 分叉段的 12 个窗口偏小、偏暗，虽然能读，但不够"多到让人迷失"。
- 截断的红线只有一条，缺少"线以下是废弃区"的空间感。
